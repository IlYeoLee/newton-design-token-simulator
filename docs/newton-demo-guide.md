# NEWTON 시뮬레이터 — 시연·발표 가이드 (D12–13)

배포: https://ilyeolee.github.io/newton-design-token-simulator/

## 한 줄 메시지
> NEWTON 시뮬레이터는 3D 게임이 아니라, **숙련자의 움직임이 NEWTON 토큰 규칙을 거쳐
> 사용자 발밑/벽면의 "배울 수 있는 단서"로 번역되는지, 그리고 그 하드웨어가 물리적으로
> 성립하는지**를 검증하는 장치다.

---

## 시연 순서 (약 8분 · 화면 녹화용)

### 0. 열기 (30초)
- 배포 링크 열기. 좌패널 = 원본 데이터 출처(Fukuchi/Bandai/SportVU/Zenodo — 전부 실측·CC),
  디자인 토큰 슬라이더, 세션. 우측 = 3D 투사 시뮬.
- 포인트: "빔 하나 안 든 게 아니라, 실측 데이터 → 토큰 → 투사 UI를 전부 시뮬로 검증."

### 1. 러닝 세션 — 살아있는 체험 (2.5분)
- **`세션 시작`** → 자동 1인칭. 발 두 번 탭(👣)으로 시작 후 **손 떼기**.
- 흐름: 스트레칭(발목·종아리·스윙·박자걷기, 봇이 3인칭서 시연) → 사전 익히기 → T-2 카운트
  → **실전 라이브**(진짜 달리는 시점·전진, BOOST 화면 발광·감속 정지) → 리포트.
- 포인트: "말만 하는 게 아니라 렙을 실제로 가이드하고, 무입력이면 자동 진행되며,
  실전은 실측 모캡으로 진짜 달리는 시점이 나온다."

### 2. 물리 검증 — 이 하드웨어가 되는가 (2분) ★핵심 차별점
- **모션 검증 · `스트레칭`/`킥`**: 실측 모캡을 봇에 입혀 무릎 투사 오차 실측
  → 스트레칭 avg 1.2cm / 킥 max 6.5cm (판정창 ±15cm 대비 여유). "스트레칭 중에도 투사 성립."
- **`복싱 그림자·거리 검증`**: PASS — 유닛이 유저 앞 1.9m라 펀치가 빔에 1.54m 못 미침 →
  타겟 그림자 0%. "복싱 = 섀도복싱 + 원거리 시각 큐. 제약은 공간 깊이 3.9m."
- **농구 탭 열고 3인칭**: 무릎 유닛이 봇 컷을 따라 움직임 → 전방 런지 순간 플랜트가
  투사 콘 밖(시야내 0~1/2). "무릎 유닛은 러닝 직선 착지엔 되지만 농구 다방향 풋워크의
  정밀 플랜트는 못 쏨 → **방향·리듬 큐가 답**. 이런 물리 한계를 시뮬이 발견."

### 3. 토큰 시스템 — 하나의 문법 (1.5분)
- **`복싱`/`농구` 탭** 전환하며: 같은 마크/링/화살표 문법이 지면·벽면에 공통 적용.
- **🎛 에디터**: 팔레트·세션 타이밍·토큰 지오메트리 슬라이더가 **실시간 반영**(마크 크기
  키우면 즉시 커짐), 스테이지 멘트 편집, 프리셋 저장. "디자이너가 실제 렌더 위에서 검수."
- 문서 링크(newton-wireframe.html)로 통합 마크·핸드오프 스펙 보여주기.

### 4. 데모 투어 (1분)
- **🎬 데모 투어** → 러닝→복싱→농구 손 안 대고 자동 순회. 녹화 배경으로 틀어두기 좋음.

## 성공 기준 (외부인 테스트)
설명 없이 1인칭 데모를 보고 **"아, 숙련자 움직임을 내가 따라할 단서로 바꿔주는 거구나"**라고
말하면 성공. (D13에 팀원 아닌 1명에게 테스트 권장.)

## 정직하게 말할 한계 (강점으로)
- 봇 동작은 가진 모캡의 **근사**(동작별 정확 모캡은 미보유) — UI 검증이 목적이지 모션캡처가 아님.
- 농구 무릎유닛 정밀 플랜트 = 물리적 한계 → 방향 큐로 재설계(발견 자체가 시뮬의 가치).
- 판정·오차는 실력 슬라이더로 주입한 시뮬값(상용 센서 정확도 아님).
