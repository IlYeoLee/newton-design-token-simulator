# 검정 배경 + Unmult — 에펙 합성 정본 경로 (2026-08-06 유저 확정)

> 결론부터: **검정 배경으로 뽑아서 AE 에서 Unmult 로 빼면 전부 제대로 나온다.**
> 유저가 AE 에서 직접 확인했다. 알파 추출(`--alpha`)은 이제 **선택지 중 하나**이지
> 필수 경로가 아니다. 이 문서는 새 기기에서 리포만 받아도 그 결정을 이해할 수 있게 남긴다.

관련: `KNOWN-ISSUES.md` 「알파는 매트가 아니라 빛의 세기」(왜 같은 연산인지 실측)
· `HANDOFF-0802-ALPHA-EXPORT.md`(알파 파이프라인) · `scripts/measure_alpha_kind.mjs`

---

## 1. 왜 되는가 — 두 경로가 같은 연산이기 때문

투사는 **가산광**이다. 검정 배경 위의 픽셀 밝기가 곧 그 자리에 쏜 빛의 세기다.

- 시뮬레이터 알파 경로: `scene.js` grade 패스가 **휘도에서 알파를 만든다**
  ```glsl
  float L = max(c.r, max(c.g, c.b));
  gl_FragColor = vec4(c.rgb, clamp(L * 1.8, 0.0, 1.0));
  ```
- AE Unmult: **똑같이 휘도를 알파로 삼는다.**

차이는 **순서뿐**이다 — 셰이더는 8비트로 굽기 전(float), 플러그인은 구운 뒤. 후자가 반올림을
한 번 더 할 뿐이라 눈으로는 같은 그림이다.

## 2. 그래서 실무에서 어느 쪽을 쓰나

| | 검정 배경 + Unmult | `--alpha` 추출 |
|---|---|---|
| 렌더 비용 | 싸다 (알파 RT·프리플라이트 없음) | 비싸다 |
| GPU 한계 | 안 걸린다 | 4K 에서 `--ss 2` 면 **전부 투명한 프레임**이 나온다(12MP 절벽) |
| 파일 | H.264/ProRes 422 로 충분 | PNG 시퀀스 / ProRes 4444 |
| 색 손실 | 없음 | 없음 |
| 어두운 톤 | 똑같이 반투명해진다(아래 §4) | 똑같이 반투명해진다 |

→ **기본은 검정 배경본.** 알파본은 이미 뽑아 둔 게 있거나, 인물처럼 잉크 알파가 필요한 경우에만.

## 3. 에펙에서 하는 법

1. 검정 배경본을 임포트 (`out/**/preview_black_bg_NOT_for_AE/` 도 같은 성질이다 —
   그 폴더 이름은 "알파본과 헷갈리지 말라"는 뜻이지 못 쓴다는 뜻이 아니다)
2. 레이어에 **Unmult** 적용 (또는 레이어 모드를 **Add / Screen** 으로 — 가산광이라 매트가 애초에 필요 없다)
3. **검사는 반드시 밝은 단색 위에서.** 검정 위에 얹으면 검정이 빠졌는지 눈으로 확인이 안 된다.

알파본(PNG 시퀀스)을 쓸 때만: Interpret Footage ▸ 알파 ▸ **Straight (Unmatted)**.
Premultiplied 로 읽으면 검정을 한 번 더 빼서 가장자리가 뜬다(실측: `max(RGB)/alpha` 평균 1.154,
`RGB > alpha` 픽셀 38.8% = 스트레이트다).

## 4. 한계 — 이건 두 경로 공통이다

- **휘도 알파는 어두운 톤을 반투명하게 만든다.** 회색 머리카락(휘도 0.10)은 알파 0.18 이 된다.
  → 알파 경로엔 `--alphagamma 0.5` 손잡이가 있고, Unmult 경로에선 **Levels 로 알파를 들어 올린다**(같은 일).
- **인물은 예외다.** 인물 판은 가산이 아니라 잉크(커버리지 알파)라 휘도로 뽑으면 검정·머리카락이
  사라진다. 인물만은 `--layer person`(실루엣 알파) 또는 `personout.html` 경로를 쓴다.
- 발자국·화살표·판정 토큰처럼 **순수한 빛**인 것에는 이 한계가 안 걸린다.

## 5. 확인 도구

```bash
node scripts/measure_alpha_kind.mjs <PNG>   # 프리멀티 / 스트레이트를 한 수치로 가른다
```
