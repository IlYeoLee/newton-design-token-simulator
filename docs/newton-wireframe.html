처음엔 밟게 하고, 중간엔 이해시키고, 실전에선 예측하게

NEWTON 세션은 스트레칭(A) → 사전 익히기(B) → 실전 운동(C)으로 흐른다. A는 가이드 친절도 높음·웨어러블 개입 약함, B는 가이드가 가장 많고 반복 보조 중심, C는 가이드 축소·지속 수행 중심. 이 문서는 3개 Pack을 동작 단위 프레임으로 분해해 지면·벽면에 실제로 무엇이 뜨고, 누가 어떤 멘트를 하고, 몇 분이 걸리는지 보여준다.

앱은 세팅까지. 운동 중 흐름은 몸으로 — 지면/벽면 UI · 숙련자 보이스 · 햅틱 · 웨어러블 · 발 두 번 탭.
STEP-TYPE · 티칭 (A·B단계)

직접 밟고, 맞추고, 따라 하게

"여기를 밟아", "이 순서로", "지금 1단계". 큰 토큰 + 문장 텍스트 + 숙련자 워밍업·코칭 큐. 코칭 큐는 한 번에 한 단서만.

PREDICTION-TYPE · 수행 (C단계)

방해 없이 예측하게

"다음 발이 어디로", "곧 전환". 선행 단서 최소·문장 금지(단어 1~2개). 숙련자 실전 큐는 원본 리듬 그대로.

왜 AR 글라스가 아니라 프로젝션인가

얼굴 위 0g

격한 움직임에 기기가 없다

복싱 위빙·스텝백 급제동에서 얼굴 착용 기기는 흘러내리고 땀에 젖고 충격에 위험하다. NEWTON은 몸에 쓰는 것이 없고 하체 웨어러블이 오히려 착지를 보조한다.

시선이 자연스럽다

단서가 시선 낙하점에 있다

러너는 발이 아니라 전방 1.4m+ 지면을 본다. 프로젝션은 그 자리에 그린다. AR은 눈앞 레이어라 초점 전환·어지러움이 생기고, 지면 단서는 시선 이동 없이 흡수된다.

같이 보인다

공유 필드가 된다

투사된 단서는 친구도 본다. 두 스테이션을 결합하면 투사면이 넓어져 2인 플레이(시나리오 05)로 확장. AR 글라스의 화면은 혼자만의 것이다.

이 문서의 범위 — 정직한 선긋기

이 문서가 하는 일

구조·로직 가이드 (Lo-Fi)

무엇이 · 언제 · 어디에 · 누구 목소리와 함께 뜨는지, 상태가 어떻게 전이되는지, 사출 모드가 단계별로 어떻게 다른지 — 설계 결정을 고정하는 문서다.

이 문서로 안 되는 일

시각 가이드는 아직 아니다 (Hi-Fi 별도)

발자국 에셋 실물 스펙, 모션 타이밍 커브(수축·소멸 이징), 투사 룩(휘도·블러·재질 위 발색), 상태 전이 애니메이션은 여기 없다 — 3D 시뮬레이터에서 실장하며 검증해야 할 몫. 이 문서는 그 실장의 사양서다.

00-B · Minimal Token System

최소 토큰 디자인 시스템 — 모양 · 상태 · 판정이 하나로

원칙은 세 채널 분리 — 모양 = 역할, 색 = 상태, 모션 = 타이밍. 색은 상태 표현에만 예약하고(좌/우 구분에 색 쓰지 않음), 상태는 항상 색+모션 이중 부호화(색약 대응). 그리고 시스템 전체는 아래 3계층 하나로 통합된다 — 화면의 모든 요소는 이 셋 중 하나다.

레이어 1 · 판정 토큰

① stepMark · ⑤ targetMark

밟거나·치거나·유지하는 판정 대상. 7상태 머신을 온전히 갖는 유일한 계층 — Success/Miss/Hold는 여기에만 존재한다.

레이어 2 · 문맥 토큰

③ directionGuide · ④ pathLane · ⑥ ghost

읽는 대상(방향·경로·폼). 판정하지 않으므로 상태가 없다 — 출현(페이드인)·표시·소멸뿐. Warning 시 전역 UI 축소에만 반응.

레이어 3 · 종속 요소

② orderPulse · 링 2종

혼자 못 뜬다. ②는 부모 토큰(①⑤)에 붙는 배지, timingRing/holdRing은 부모의 Active/Hold 상태 그 자체의 시각화.

사출 방식 2모드 — 밟는 UI와 예측하는 UI는 다른 기계다

같은 "발자국"이라도 직접 밟는 단계(A·B)와 흐름을 예측하는 단계(C)는 투사 위치·모양·감지 로직이 전혀 다르다. 시나리오도 이 두 모드로 분리해 설계한다.

MODE 0 · WATCH-TYPE — 정지 시청

"멈추면 투사면은 스크린이 된다"

사용자가 정지 상태일 때 지면/벽면에 실영상 클립(3~8초 루프)을 재생 — Pack 프리뷰, B단계 도입, Miss 누적 시 다시 보기. 시청이 끝나면 같은 자리에서 ghost 궤적형(발자국 리플레이)으로 크로스페이드 → 내 차례.

  • 정지 감지 — 속도 ≈ 0 + 시선 하향일 때만 재생
  • 시청 키스톤 보정 — 서 있는 눈높이 기준 왜곡 보정
  • 클립→궤적 정렬 — 영상 속 발 위치와 실측 궤적을 같은 좌표에 동기
MODE 1 · STEP-TYPE — 스트레칭·사전 익히기

"여기를 밟아라" — 발 모양 이미지를 직접 밟는다

다음 발을 디딜 위치에 실측 크기 발 모양 이미지(좌/우 구분)를 투사. 사용자는 정지 또는 저속이므로 DEAD 존(0~1.4m) 규칙이 면제 — 발밑 투사가 유효한 유일한 모드. 텍스트·숫자·유지 링 결합 가능.

  • 보행 속도 추정 — 사용자 속도에 맞춰 다음 발 이미지 타이밍 결정
  • 보폭 이미지 제시 위치 결정 — Pack 보폭 × 사용자 캘리브레이션(내 몸 기준)
  • 뒤꿈치 접촉 감지 + 좌우 발 이미지 전환 — 밟힘을 감지해야 다음 발이 뜬다
MODE 2 · PREDICTION-TYPE — 실전

"앞사람의 발자국" — 2·3번째 위치를 미리 보여준다

두 번째·세 번째 발 위치를 존 원으로 선행 표시(투명도 1.0/0.6/0.35). 사용자는 위치 관계를 보고 보폭을 스스로 예측 — 한 걸음 앞서 걷는 보이지 않는 사람을 따라가는 감각. DEAD 존 규칙 적용, 발밑 무효.

  • 착지 예측 — 현재 속도·보폭 기반 다음 착지점 계산 (0.74s 전 출현 보장)
  • 존 판정 — 반경 = 허용창, 접촉 감지는 IMU 착지 이벤트로
  • 밀도 조절 — 피로·난이도에 따라 선행 개수 2~4개 가변

Q. 발자국은 발자국 모양이어야 할까? — 모드가 답을 정한다

결론

Step-type = 발 모양 / Prediction-type = 존 원

① Step-type(A·B)에서는 발 모양이 맞다 — 정지·저속이라 정렬 가능하고, 좌/우·방향·보폭이 전부 유효한 정보다. 뒤꿈치 접촉 감지와도 계약이 일치("이 발을 여기 놓아라").
② Prediction-type(C)에서는 발 모양이 해롭다 — 판정은 발 중심+타이밍뿐인데 모양은 각도까지 요구하는 것처럼 보인다(정확도 집착). 착지 0.74s 전 출현이라 정렬은 물리적으로도 불가능.
③ 그래서 모양은 단계가 아니라 사출 모드가 결정한다. 밟는 UI = 발, 예측하는 UI = 존.

핵심 원칙

토큰 반경 = 판정 허용창

원의 크기가 곧 허용 오차 — 보이는 것 = 판정되는 것.
입문 큰 원 = ±21cm / 기본 = ±15cm / 원본 근접 작은 원 = ±9cm.
난이도 토글이 시각과 판정을 동시에 조절하므로, 별도의 "숨은 판정선"이 없다. 사용자는 원 안에 들어가면 성공이라는 계약 하나만 기억하면 된다.

04 · Motivation Loop

동기 · 보상 — 시작하게 만들고, 계속하게 만든다

동기는 운동 전(넛지) — 중(Situation Cue) — 후(리포트·성장 수치) 세 겹이다. 운동 중 보상은 점수판이 아니라 성공 순간의 짧은 신호. 실패에 벌점 없음.

운동 전 — 스테이션 넛지 (실제 멘트)

저장 PACK 리마인드"저장해둔 커리 스텝백, 오늘 3분만 해볼까요?"
최근 본 콘텐츠"아까 본 그 러닝 리듬, 지금 바로 바닥에 띄워볼 수 있어요."
이어하기"지난번 멈춘 구간부터 다시 이어갈까요?"
상황 기반"오래 앉아 있었어요. 조용한 실내 Pack으로 몸을 풀어볼까요?"
친구 초대"친구가 보낸 짧은 챌린지 Pack을 열어볼까요?"
입문 추천"처음 해보기 좋은 워밍 스텝 러닝이 준비됐어요."
