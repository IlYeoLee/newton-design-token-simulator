## 2. 이미지(썸네일) 처리

케이시 썸네일은 **투명도가 아니라 필터로** 처리한다. 원본 사진의 검정을 없애 빔 정직성을 지킨다.

```html
<div class="hdr-photo">
  <div class="ph" style="left:-21px;top:-8px;width:260px;height:404px;">
    <img src="assets/casey.png">
  </div>
  <div class="blur"></div>
</div>
```

- `.hdr-photo` — `border-radius:44px; overflow:hidden` (원형 마스크)
- `.blur` — 뒤에 깔리는 소프트 판(아웃라인 대용)

**루마 온도색 변환**(검정 제거 · 코랄 모노톤)이 필요할 때 쓰는 필터 정본:

```css
filter: grayscale(1) contrast(.55) brightness(1.38) sepia(.55) saturate(2.4) hue-rotate(-18deg);
```

> 최종본에서는 이 필터를 떼고 원본 이미지를 그대로 쓰되, 뒤의 `.blur` 판과 카드 배경이
> 검정을 눌러 준다. 필터를 다시 쓸 일이 있으면 위 값을 그대로 쓸 것.

## 4. 시뮬레이터에 합성할 배경을 미리 깔기

에펙에서 합성하지 않고 **시뮬레이터 안에 실사 배경을 깔고 통째로 뽑는다.** 알파·키잉 단계가
사라져서 가장자리 등고선·검정 소실·프리멀티 문제가 원천적으로 안 생긴다.

### 준비
```
public/_bg/wall.png        정면 배경
public/_bg/wall_side.png   측면 배경
```
`scenes.html` 의 `BGS` 배열에 한 줄 추가하면 드롭다운에 뜬다.

### URL
```
index.html?alpha=1&scene=BX_READY&bg=/_bg/wall.png&bgdim=0
```

| 파라미터 | 의미 |
|---|---|
| `alpha=1` | 렌더러 알파. **항상 붙인다** — 생성 시점에 정해져서 나중에 못 켠다 |
| `bg=<url>` | 3D 실내를 끄고 실사 배경만 남긴다 |
| `bgdim` | **음수 = 밝게 · 양수 = 어둡게** (−0.6 ~ 0.9) |

### 배경 이미지 권장 규격
- **출력 해상도로 미리 축소**할 것. 8208×5348 원본은 디코드에만 175MB(가로×세로×4).
  3840 폭으로 줄이면 33MB. 출력이 3840이면 배경도 3840이면 충분하다.
  ```
  ffmpeg -i 원본.png -vf scale=3840:-1 배경_3840.png
  ```
- 영상 배경이면 **올-인트라**로 변환(프레임별 시크가 즉시 끝난다).
  스크립트가 이 변환 + 출력 크기 축소 + 16:9 센터크롭을 한 번에 한다:
  ```bash
  node scripts/make_bg_proxy.mjs --src "<원본.mov>" --w 2560
  # → public/_bg/<이름>_2560.mp4   (crf 12 · -g 1 · yuv420p, 위 정본값 그대로)
  ```
  안에서 도는 명령은 이것과 같다:
  ```
  ffmpeg -i 배경.mov -vf scale=2560:1440:force_original_aspect_ratio=increase,crop=2560:1440 \
         -an -c:v libx264 -crf 12 -g 1 -bf 0 -pix_fmt yuv420p 배경_allI.mp4
  ```
  **원본 .mov 를 그대로 물리면 안 된다.** long-GOP 라 프레임마다 앞 키프레임부터 다시 디코드하고,
  4096×2160 디코드 버퍼가 GPU 예산을 먹어 조용히 빈 프레임이 나온다.
  실측: 4096×2160 17초 h264 → 2560×1440 올-인트라 211MB(러닝) · 183MB(복싱).
- **프록시를 만든 뒤 vite 를 재시작할 것.** 뜬 뒤에 생긴 public/ 파일은 안 나간다 —
  mp4 요청에 index.html 이 돌아오고(`Content-Type: text/html`) 브라우저는
  `DEMUXER_ERROR_COULD_NOT_OPEN` 만 뱉는다. 원인이 전혀 안 보인다.

### ⚠ 함정
- 배경은 **캔버스 바로 부모**(`renderer.domElement.parentElement`)에 깔아야 한다.
  body 에 깔면 `mix-blend-mode` 가 중간 컨테이너와 섞여 "가산이 안 먹는다".
- **영상 배경은 CSS 로 못 깐다.** 같은 부모 안에 `<video id="__bgvid">` 를 `z-index:-1` 로 넣는다.
  음수 z-index 는 **부모·body 배경보다 아래**에 그려지므로, 부모(`main#stage`)나 body 에
  불투명 검정이 남아 있으면 배경이 통째로 검은 프레임이 된다(실측: 처음 두 번 다 이것).
  검정은 `<html>` 에만 남긴다.
- **DOM 청소가 그 `<video>` 를 지운다** — 앱의 `tickSceneStage` sweep, 익스포터의 `__sweep` 두 곳.
  둘 다 `#__bgvid` 만 예외로 뺐다. 익스포터의
  "캔버스 밖에서 보이는 요소 1건: VIDEO#__bgvid" 경고는 **정상**이다.
- 캔버스를 집을 때 `document.querySelector('canvas')` 는 **타임라인 UI 캔버스**를 먼저 잡는다.
  `renderer.domElement` 를 쓰거나, 없으면 가장 큰 캔버스를 골라라.
- 배경 지우기·무대 격리는 **매 프레임 다시** 걸어야 한다. 앱이 매 틱 되돌린다.

## 5. 에펙 합성 (마스킹 + 페더)

시뮬레이터 안에서 배경까지 합성했다면 에펙은 **마무리만** 한다.

1. **마스킹** — 투사면 영역만 남기고 잘라낸다. 평면 직교로 뽑았으면 원근이 0이라
   4점 코너핀이 정확히 맞는다(왜곡 보정 불필요).
2. **페더** — 마스크 가장자리 페더로 경계를 녹인다. 빔은 가장자리가 딱 떨어지지 않는다.
3. **블렌드 모드**
   - `Screen`/`Add` — 오늘날 프로젝터의 물리. 밝은 면에선 날아간다
   - `Normal` + 투사 세기 0.88~0.93 — **미래 풀컬러 기술 가정이면 이쪽.** 벽 질감이
     10%쯤 비쳐 "표면에 얹힌" 단서만 준다
4. **표면 질감 곱하기** — 배경을 흑백 복제해 투사 레이어에 Multiply. "얹은 티"가 제일 많이 빠진다.
5. **원거리 감쇠** — 먼 쪽 15~25% 어둡게. 실제 빔은 거리가 멀수록 어둡다.

> 검은 배경으로 뽑아 에펙에서 키잉할 거면 **Effect › Keying › Extract**(Channel: Luminance).
> `Black Point`·`Black Softness` 를 실시간으로 만질 수 있어, 추출 시점에 값을 굽는 것보다 낫다.

## 6. 영상화 파이프라인 — 자동 추출

### 기본 명령
```bash
npx vite --port 5199 --strictPort --host 127.0.0.1     # 먼저 켤 것

node scripts/export_video.mjs --scene BX_READY --sport boxing --play \
  --dur 8 --fps 29.97 --w 2560 --ss 1 --out out/SCENE_2K
```

### 옵션
| | |
|---|---|
| `--scene <ID>` | 씬 스테이지 모드. 화면녹화하던 그 화면. **`--sport` 를 안 주면 씬 id 에서 유도**(`BK_`→농구·`BX_`→복싱·나머지 러닝) |
| `--w` | 출력 가로 px |
| `--ss N` | **N배로 렌더한 뒤 `--w` 로 되돌린다.** PNG 만 큰 해상도로 남는다 |
| `--bg <파일>` `--bgdim` | 실사 배경. 사진·영상 둘 다. 영상은 `--scene` 필수(앱의 `<video>` 경로) |
| `--dur` `--fps` `--t0` | 길이 · 프레임레이트 · 시작 시각 |
| `--fp` | **1인칭**(러닝·농구의 실제 시야). 종목별 화각·VOR·가독 보정이 딸려 온다 |
| `--zoom --pan --tilt --dolly` | 촬영 조정. **1인칭에서도 먹는다** — 눈 위치는 앱이 잡고 그 위에 요/피치/화각만 얹는다. pan/tilt 단위는 라디안(슬라이더 ±1.5 = ±86°) |
| `--exposure --bloom --uix --uiy` | 노출 · 글로우 · 투사 UI 위치 |
| `--opacity --blend` | 합성. `screen` = 가산광(프로젝터 물리) · `normal` + opacity 0.88~0.93 = §3·§5 |

> 전부 `window.__sceneAdj` 로 들어간다 — **scenes.html 슬라이더가 쓰는 바로 그 객체다.**
> '지금 값 복사' 가 만들어 주는 문자열이 그대로 이 옵션들이다.

### 실사 **영상** 배경 — 러닝·복싱 전체 절차
```bash
node scripts/make_bg_proxy.mjs --src "<원본.mov>" --w 2560   # ① 프록시 (§4)
# ② vite 재시작 → scenes.html 에서 배경·시점·각도 맞추고 '지금 값 복사'
node scripts/export_video.mjs --scene P1 --play --fp --blend screen \
  --bg public/_bg/Pace_ON_Boost_On___2-2_2560.mp4 --bgdim 0.15 \
  --uiscale 1 --w 2560 --fps 29.97 --dur 4 --out out/BGCOMP_2K
```
- **`--blend screen` 이 사실상 필수다.** normal 이면 투사판의 검정 배경이 불투명 사각형으로
  바닥에 얹힌다(실측 프레임에 그대로 나왔다). 투사는 가산광이라 screen 이 물리적으로도 맞다.
  §5 의 'Normal + 0.88~0.93' 을 쓰려면 `--blend normal --opacity 0.9`.
- **`--fps` 는 배경 소스에 맞춘다.** 이 소스들은 29.97(30000/1001)이다 — §"fps 정합" 참조.
- **`--uiscale 1` 필수.** 기본값(1.25)에 배경 영상을 얹으니 18프레임에서 컨텍스트를 잃었다.

> **`.mov` 해상도 = `--w`.** 4K `.mov` 가 필요하면 `--w 3840 --ss 1`.
> `--w 1280 --ss 2` 는 2560으로 렌더하지만 `.mov` 는 1280×720 이다.

### 실측 성능 (씬 스테이지 BX_READY)
| 설정 | 출력 | 프레임당 | 8초(240f) |
|---|---|---|---|
| `--w 1280 --ss 2` | 1280×720 | 1.08초 | 4분 18초 |
| `--w 2560 --ss 1` | 2560×1440 | 1.77초 | **7분 04초** |
| `--w 3840 --ss 1` | 3840×2160 | 4.23초 | 약 17분 |

실사 **영상** 배경 + 1인칭 (러닝 P1, 실측 08-03):

| 설정 | 출력 | 프레임당 | 결과 |
|---|---|---|---|
| `--w 2560 --uiscale 1.25` | 2560×1440 | 1.45초 | ✗ **18프레임에서 컨텍스트 손실** |
| `--w 2560 --uiscale 1` | 2560×1440 | 0.95초 | ✓ 120/120 · 4초 |

- GPU 절벽은 **12MP 부근**. 4K(8.3MP)는 통과하지만 `--pad` 를 얹으면 넘어간다.
- `--uiscale` 은 4K 에서 병목이 **아니다**(2→1.0 으로 내려도 차이 없음, 실측).
  단 **배경 영상을 얹으면 얘기가 다르다** — 2560 디코드 버퍼가 얹혀 1.25 로도 넘어간다(위 표).
- 영상 배경 4K 는 **아직 안 재봤다.** 여기부터 다시 재야 한다.

### 왜 화면녹화가 아니라 익스포터인가
| | 화면녹화 | 익스포터 |
|---|---|---|
| 해상도 | 디스플레이 한계(실측 3292×1874) | 자유 |
| 프레임 | 드롭 있음(실측 19.57fps 평균) | **드롭 0** |
| 원리 | 실시간 | 가상 시계로 한 프레임씩 — 한 장에 4초가 걸려도 간격은 정확히 1/fps |

### fps 정합 — 해상도보다 먼저
소스 클립이 24fps 인데 29.97 로 뽑으면 **불규칙 프레임 반복(저더)** 이 생긴다.
- 출력을 **24fps** 로 맞추거나
- 소스를 **30fps** 로 받아라

### 산출물
```
out/<태그>.mov                        ProRes — 본편
out/<태그>_png/                       PNG 시퀀스 (렌더 원본, --ss 배)
out/preview_black_bg_NOT_for_AE/      확인용 mp4 (알파 없음 — 에펙에 넣지 말 것)
```

### ⚠ 렌더 중 금지
**리포에 파일을 쓰지 말 것.** vite 가 소스 변경으로 보고 페이지를 새로고침해 렌더가 죽는다
(`✗ --flat 실패: 렌더 카메라가 undefined`). 17분짜리를 두 번 날렸다.

## 7. 값 맞추는 흐름 (권장)

**scenes.html 이 편집기다.** 씬마다 맞춘 값은 `public/_presets.json` 한 곳에 모이고
**익스포터가 같은 파일을 읽는다** — CLI 로 값을 손복사할 필요가 없다.

1. `scenes.html` 열기 → 씬 선택 (저장본이 있으면 자동으로 걸린다. 목록에 초록 ● 표시)
2. **배경** 드롭다운 + 밝기 슬라이더 (사진·영상 공통)
3. **시점** — 평면(대지 1:1) / 1인칭(실제 시야). 러닝·농구 지면 UI 는 1인칭으로 봐야 판단이 된다
4. **합성** — 잉크(normal) / 빛(screen, 가산)
5. **촬영 조정** — 화각·좌우·상하·거리·노출·글로우·UI 위치·**UI 크기**·투사 세기
   (전부 1인칭에서도 먹는다 — 좌우/상하는 라디안 요·피치)
6. **색 보정** — 투사와 배경을 **따로** 잡는다(밝기·대비·채도·색상).
   서로 다른 광원이라 한 손잡이로 묶으면 반드시 한쪽이 틀어진다.
   구현은 CSS filter — 캔버스와 `#__bgvid` 에 각각 건다. 스크린샷에 그대로 찍히므로
   내보내기와 화면이 자동으로 일치한다. ※ **사진 배경엔 배경 색 보정이 안 걸린다**
   (사진은 캔버스 부모의 CSS 배경이라, 필터를 걸면 캔버스까지 같이 먹는다). 영상 배경만 된다.
7. **개체 삭제** — '목록 갱신' → 지금 그려지는 개체 목록. 체크하면 화면에서 뺀다.
   되살리려면 체크 해제(iframe 이 리로드된다 — 앱은 visible 을 스스로 안 되돌린다).
8. **이 씬 저장** → `public/_presets.json` 에 그 씬만 병합 저장
9. **내보내기 명령 복사** → 붙여 넣고 실행. 값은 저장본에서 읽는다

```bash
# 저장했으면 이것만으로 끝난다 — 배경·1인칭·각도·색·개체가 전부 저장본에서 온다
node scripts/export_video.mjs --scene P1 --play --uiscale 1 --w 2560 --fps 29.97 --dur 4 --out out/SCENE_2K
```

CLI 플래그를 주면 그것이 저장본을 이긴다(한 번만 다르게 뽑을 때). 색 보정·개체 삭제는
값이 많아 플래그가 없다 — **저장본이 유일한 출처**다.

### ⚠ 합성은 기본이 **빛(screen)** 이다 — 잉크로 두면 검은 사각형이 생긴다
지면 투사 판(`floorGL.mesh`)에 **어두운 면**이 있다. 잉크(normal)로 얹으면 그게 실사 배경 위에
**불투명 검정 사각형**으로 남는다(유저: "달리기에서 이상한 검정색 무언가 보여 계속").
1인칭 러닝에서 화면 아래쪽에 크게 나온다.

- 화면·익스포터 기본값을 screen 으로 바꿨다. **투사는 가산광이라 검정을 못 쏘는 게
  물리적으로도 맞다**(§1). 배경이 없으면 backdrop 이 검정이라 screen 과 normal 이 같은 그림이다.
- 범인 찾는 법(이번에 쓴 방법): 개체를 하나씩 `visible=false` 로 끄면서 그 자리 픽셀 밝기를 잰다.
  레이캐스트는 **안 통했다** — three 의 Raycaster 는 부모의 visible 을 안 보므로 이미 꺼진
  개체까지 잡아 준다. 실측으로 `floorGL.mesh` 가 36.4 → 98.8 로 제일 크게 밝아졌다.
- **남은 것**: 잉크(normal) 모드에서는 아직 그대로다. 판 캔버스의 어두운 면을 없애야
  근본 해결인데, `floorgl.js` 에 전면 어두운 fill 은 없다 — 카드/에셋 중 하나로 보인다. 미확인.

### ⚠ 지면 씬에서 벽 판이 서 있었다
`sceneStageBg` 가 바닥·벽 투사면을 **둘 다** 켜고 있었다. 러닝·농구(지면 씬)에서 복싱용 벽 판이
카메라 앞 1.9m 에 그대로 서 있었다(내용도 틀린 판이다). 이제 그 씬의 투사면 하나만 켠다.

### ⚠ 저장본 관련 함정
- 저장본은 **`/__presets` 미들웨어**로 읽는다. `public/_presets.json` 을 직접 fetch 하면
  vite 가 뜬 뒤에 생긴 파일이라 index.html 이 돌아오고, 저장본이 **조용히 무시된다**(실측).
- 씬 버튼은 저장본 로드를 **기다린 뒤** 동작한다. 안 기다리면 부팅 직후 누른 씬에 기본값이
  걸리고, 그대로 저장하면 애써 맞춘 값이 기본값으로 덮인다(실측으로 한 번 날렸다).
- **UI 크기는 원본 배율을 한 번만 잡으면 안 된다.** 부팅 첫 프레임의 `mesh.scale` 은 아직
  앱이 안 쓴 (1,1,1) 이라, 그걸 원본으로 굳히면 1600×2670 짜리 판이 1600m 로 그려져
  **UI 가 통째로 사라진다**(유저: 정보 UI 안 보여). 우리가 마지막에 쓴 값과 다르면 앱이 새로
  쓴 것이니 그때만 원본을 다시 잡는다(자가 치유).

## 8. 검수 — 뽑고 나서 반드시

```bash
node scripts/verify_alpha.mjs out/*.mov      # 투명 배경 · 빈 프레임
node scripts/measure_flicker.mjs out/*_png   # 깜빡임(프레임 간 알파 변화)
```

- ⚠ **이 두 검수는 알파 추출용이다.** 실사 배경을 깔고 뽑은 합성본은 전부 불투명(알파 255)이라
  `verify_alpha` 는 "모서리 불투명 = 실패"로 읽히고, `measure_flicker` 는 알파 차이만 보므로
  **항상 0.00% 로 통과한다 — 아무것도 증명하지 못한다**(실측: 러닝 2K 합성본 120프레임 0.00%).
  합성본의 시간축 검수는 `preview_black_bg_NOT_for_AE/*.mp4` 를 눈으로 돌려 보는 게 현재 최선이다.
- **정지 프레임 한 장으로 시간축 아티팩트를 판단하지 마라.** 잔상·깜빡임은 프레임 간
  변화량으로만 잡힌다. 이걸로 여러 번 오판했다.
- 익스포터는 가상 시계라 **실시간에서만 나는 버그를 못 본다**(예: 필드 갱신 스로틀 어긋남).
  최종 판단은 실시간 화면에서.
