산출물에 **요청하지 않은 연출을 얹지 않는다.** 카메라 무브, 레벨/색보정, 비네트,
블러, 흔들림 — 전부 유저가 직접 한다.

**Why:** 2026-08-06, 에펙 조립 스크립트에 3D 카메라·심도·속도 블러·비네트·레벨 보정을
넣어서 냈다. 유저 반응: *"레벨조정 같은건 왜한거야...."* / *"그냥 적당히 실측사이즈 +
실제 속도 + 발자국 방향 개선 + 글로우 팡팡 만 넣고 아무것도 건들지않으면 차라리 내가
나중에 카메라 등등으로.. 하는게 맞지않아"* / *"일단 과하게 뭘 하지마"*.
토파즈로 만든 배경에 레벨을 걸었던 게 특히 문제였다 — 원본을 건드린 셈이다.

**How to apply:** 요청 목록을 그대로 이행하고 거기서 멈춘다. 연출을 제안하고 싶으면
**만들지 말고 물어본다.** 스크립트를 낼 때도 임포트·정렬·매트 같은 기계적인 일만 하고,
미적 판단이 들어가는 값은 상수로 빼서 유저가 고치게 한다.

같은 맥락의 실수 — 크기·각도를 감으로 정하지 않는다. 유저:
*"너가 임의로 하면서 발자국 크기가 다 깨졋어"*. 코드 상수나 실측에서 계산해 근거를
같이 제시한다. 못 재는 값(사진 한 장에서 초점거리)은 **가정임을 명시**한다.
